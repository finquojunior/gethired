# Sweep — 21 Sep 2026

Triggered by the "Something went wrong" page Lakshmi hit while rating a
candidate at Applied, and the report that "everything is broken" after
today's pushes. Two independent read-only reviews covered every file under
`app/`, `lib/`, `components/` (excluding generated `components/ui/`), the
public routes, scripts and tests; each finding below was re-verified in the
code before it was fixed or listed.

## What actually broke today

### 1. The error page (Sentry GETHIRED-6) — fixed, deployed as `fef81c0`

Not a code bug. The 16:28 deploy (`8f57ed3`) added a new client component to
the candidate page. Any tab opened before that deploy still ran the previous
JavaScript bundle. Its next server response (the re-render after "Save
feedback", or a Prev/Next click) referenced a module that bundle never had,
so React threw `e[o] is not a function` from the webpack runtime. "Try
again" re-renders with the same stale runtime, so it fails the same way; only
a hard reload (F5) helps. The rating itself was saved before the page failed.

Vercel's Skew Protection prevents this but is a paid feature. Both error
boundaries now recognise the deploy-skew error family and hard-reload once
(one-minute cooldown, so a real bug still shows the page). Tabs that were
open before `fef81c0` will hit it one final time, then be on the new bundle.

Sentry's `release` tag was the previous commit, and the stack was entirely
inside `react-server-dom-webpack` — that pair is the signature of a stale
bundle, not of app code.

### 2. Bulk-action progress bar stuck for 30 s — fixed

`8f57ed3` made bulk actions return their result instead of redirecting.
`BulkProgress` only cleared on a URL change, so after every bulk move it
sat on "Processing N candidates…" until its 30 s timeout. It now also clears
when the form stops being pending.

### 3. Double stall watchdog — fixed

A `SubmitButton` inside a `ResultForm` armed two 15 s timers; the button's
one reloads the page and would wipe the toast the form had just shown.
`SubmitButton` now waits 20 s, so the form's in-place refresh always wins.

## Not from today, but it is why email "is slow"

**The 15-minute cron never ran every 15 minutes.** GitHub Actions' schedule
is best-effort; over the last four days it fired every 2–5 hours, with a
5.4 h gap this morning. That is the Sentry `mail-cron` outage (155 missed
check-ins), and it is why failed-send retries, interview and task reminders,
feedback nudges and auto-close all ran hours late.

Fix in this change set: migration `20260921120000_mail_cron_pg_cron.sql`
schedules the tick from pg_cron inside Supabase, calling `/api/cron` through
pg_net with the URL and bearer token read from Vault. **It needs two manual
steps in production**, documented in `docs/deploy-checklist.md`:

```
npx supabase db push
-- then once, in the SQL editor:
select vault.create_secret('https://hiring.finquo.ai/api/cron', 'cron_url');
select vault.create_secret('<the CRON_SECRET value from Vercel>', 'cron_secret');
```

Also fixed while there: a failed send added 3 to `attempts` (one per
configured service), so the cron's `attempts < 3` retry never fired — a
transient Resend outage permanently failed candidate emails. It is now one
attempt per burst.

## Security fixes

| Where | Problem | Fix |
| --- | --- | --- |
| `openings/actions.ts` `updateTaskMaterials` | A pre-uploaded brief path was accepted with only a prefix check, so any opening member could point a stage at another opening's file and then read it. | The task upload-url route now signs the path for the opening; the action verifies it (same scheme the resume flow already used). |
| `candidates/actions.ts` `addCandidate` | The posted `stageId` was written unchecked, so a stale or crafted form could park a candidate in another opening's stage. | Stage must belong to the opening, else null. |
| `resumes` bucket | No `file_size_limit`; the 5 MB cap was client-side only. | Migration `20260921120100_resumes_size_limit.sql`. |
| `/c/[token]/book`, `/c/[token]/withdraw` | The only candidate POST routes without a rate limit. | Added, same shape as siblings. |
| Both upload-url routes | Shared one rate-limit bucket with different limits. | Separate keys. |
| `/api/errlog`, all upload-url routes | A JSON body of `null` threw → 500 → reported to itself. | Reject non-object bodies with 400. |

## Reliability fixes

- **Candidate routes no longer wait for email before responding.** `book`,
  `rebook`, `reschedule`, `withdraw` and `task` awaited up to a minute of SMTP
  and API calls after the row was already committed — the "server done,
  response lost" class. They now send via `after()`, as the apply route
  already did.
- Server-side errors are written to `error_log` directly instead of through
  an HTTP hop to `/api/errlog`, which rate-limits 20 per 5 min per IP and was
  silently dropping our own reports.
- `tx()` no longer masks the original error when `rollback` itself fails.
- Task reminders: a candidate with two task stages now gets the second
  reminder (dedupe was "ever sent", now a 2-day window like interviews).
- iCal invites escape `; , \` in the summary, description and location.
- `updateTaskMaterials` revalidates the task page; "Save task" used to
  toast success while the page kept showing the old brief until a reload.
- Saving a rating on a stale form (stage deleted or re-created) now flashes
  "form was out of date" instead of bouncing to the dashboard with a
  "no access" error. CSV import on an opening with no form row redirects
  with a message instead of throwing. Both errors now have flash text.
- Form builder: a missing draft row is a 404, not a crash. Candidate page:
  the slot picker is keyed on the current interview stage, so a completed
  first interview no longer hides booking for a second one.
- Openings list: "1 candidates" (int8 count was compared as a string).
  Dashboard "held interviews" count now matches the Interviews list.
- Board drag-and-drop: the toast no longer claims "candidate emailed" and
  a zero-row move (candidate not active / already there) reads as an error.

## Still open — worth doing, in rough priority

1. **Candidate-page actions are half-converted.** `bulkPipeline`,
   `completeInterview` and the reschedule decisions return a result and
   refresh in place; `updateCandidate`, `staffBookSlot`, `staffCancelSlot`,
   `reopenInterview`, `markNoShow` and `addFeedback` still redirect with
   `?ok/?e`. One page, two patterns. Converting the rest lets `safeBack` /
   `withParam` and the URL-flash parsing go. Deliberately not done today: it
   changes the response shape for forms already open in tabs.
2. **`lib/ratelimit.ts` is per-instance memory**, so on Vercel the login
   brute-force limit resets on every cold start. The deploy checklist already
   accepts this and leans on Vercel's WAF; a Postgres-backed limiter with the
   same signature is ~15 lines plus a table if that stops being acceptable.
3. **`lib/db.ts` starts the local cron timer as an import side effect** (49
   importers). It belongs in `instrumentation.ts` `register()`.
4. `ORG_NAME` / `SUPPORT_EMAIL` / `APP_URL` live in `lib/email.ts`, so the
   root layout and every candidate page import the mail module and `pg`. A
   dependency-free `lib/org.ts` fixes that.
5. Duplicates that could each become one helper: the email regex (7 copies),
   the task-deadline SQL (3), the candidate-route `back()` + application
   lookup (8 routes), the browser-to-storage upload dance (3 components),
   `SubmissionField` type (2), the UTC stamp formatter (2).
6. `lib/zip.ts` (72 lines, store-only) could be `fflate`'s `zipSync` (8 KB,
   zero deps) if exports ever need compression. Nothing else here warrants a
   new dependency: CSV, session cookies, body validation and iCal are each
   under 40 lines and tested.
7. Untested pure logic: `storage.getFile` traversal guard, `ratelimit`,
   `tz.orgTimeToUtc`, `email.render/icsEvent`, `auth.verify*`. Most are
   blocked by `@/` imports under `node --test`; splitting the pure parts out
   makes them testable.
8. Sentry GETHIRED-5 "N+1" on the candidate page is the per-email-row
   query pattern in `notifyStage`, not the page's `Promise.all`; low impact.
9. Non-numeric ids (`/app/candidates/abc`) reach Postgres as `NaN` and land
   on the error page instead of 404 — cosmetic, ten pages.
10. Task submission and apply save files before validation finishes, so a
    later validation error orphans the stored file.
